On Android, the plugin uses Google Health Connect. Health Connect may not be preinstalled, so check its availability at runtime and guide the user if needed:

```dart
final status = await health.getHealthConnectSdkStatus();
final available = await health.isHealthConnectAvailable();
if (!available) {
  await health.installHealthConnect();
}
```

See [Health Connect](/docs/flutter-plugins/health/health-connect) for the status values and the install flow.

## Declare permissions in AndroidManifest.xml

## Request runtime permissions

For activity-related data (steps, workouts), request `ACTIVITY_RECOGNITION` at runtime. For distance in workouts, optionally also request `ACCESS_FINE_LOCATION` or `ACCESS_COARSE_LOCATION`.

```dart
import 'package:permission_handler/permission_handler.dart';

await Permission.activityRecognition.request();
await Permission.location.request();
```

See [Android runtime permissions](/docs/flutter-plugins/health/permissions#android-runtime-permissions) for the complete flow.

## Enable history and background access

The optional `READ_HEALTH_DATA_HISTORY` and `READ_HEALTH_DATA_IN_BACKGROUND` permissions in the manifest above cover historic and background reading. On devices that support these capabilities, detect and request them with:

| Capability | Check support | Request access |
| --- | --- | --- |
| Historical data | `isHealthDataHistoryAvailable()` | `requestHealthDataHistoryAuthorization()` |
| Background reading | `isHealthDataInBackgroundAvailable()` | `requestHealthDataInBackgroundAuthorization()` |

See [Historical data access](/docs/flutter-plugins/health/health-connect#historical-data-access) and [Background data access](/docs/flutter-plugins/health/health-connect#background-data-access) for examples.

---
title: CARP Debug Toolkit
description: An in-app debugging toolkit for CARP (and any) Flutter apps.
icon: Bug
---

`carp_debug_flutter` adds a floating button to your app. Tapping it opens a self-contained debug menu that is independent of the host app's widget tree: it renders in its own theme, localization and navigator, so it keeps working when a screen throws or navigation breaks.

The package is designed mainly for CARP apps. It ships adapters for `shared_preferences` and the `sembast` database, and a runtime override layer for the `--dart-define` launch arguments that CARP apps rely on. It works in any Flutter app.

## Features

<Cards>
<Card title="Environment and servers" icon="Server" href="/docs/flutter-plugins/debug-toolkit/environment">

Switch the deployment server and override any `--dart-define` launch argument at runtime, then apply the change live or restart the app.

</Card>
<Card title="Shared preferences" icon="Settings" href="/docs/flutter-plugins/debug-toolkit/built-in-tools#shared-preferences">

Inspect, search, edit, add and delete any key, including the CARP user data.

</Card>
<Card title="Database" icon="Database" href="/docs/flutter-plugins/debug-toolkit/built-in-tools#database">

Browse the local `sembast` database: list stores and records, delete records and clear stores.

</Card>
<Card title="Device and app" icon="Smartphone" href="/docs/flutter-plugins/debug-toolkit/built-in-tools#device-and-app">

Device and app metadata (model, OS, version, build) and screen metrics.

</Card>
<Card title="Logs and errors" icon="Terminal" href="/docs/flutter-plugins/debug-toolkit/built-in-tools#logs-and-errors">

Captured `debugPrint` output, framework errors and uncaught async errors.

</Card>
<Card title="Custom tools" icon="Extension" href="/docs/flutter-plugins/debug-toolkit/custom-tools">

Add your own screens to the debug menu by implementing `DebugTool`.

</Card>
</Cards>

<Callout type="warning" title="Limitation">

The toolkit handles exceptions, crashed screens and broken navigation. A *synchronous* infinite loop on the UI isolate, however, freezes all Dart rendering, including the toolkit.

</Callout>

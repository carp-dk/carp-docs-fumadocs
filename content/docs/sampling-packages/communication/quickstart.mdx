The finished app reads calls, text messages and calendar events on a schedule and prints them with phone numbers and texts hashed.

## Prerequisites

- The setup in [Installation](/docs/sampling-packages/communication/installation), including the CARP Mobile Sensing (CAMS) setup it builds on.
- A physical phone with some calls, text messages and calendar events. On iOS, only the calendar is collected.

## Complete example

Replace the contents of `lib/main.dart` with:

```dart title="lib/main.dart"
import 'dart:convert';

import 'package:flutter/material.dart';
import 'package:carp_core/carp_core.dart' hide Smartphone;
import 'package:carp_mobile_sensing/carp_mobile_sensing.dart';
import 'package:carp_communication_package/communication.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  CarpMobileSensing.ensureInitialized();

  // 1. Register the sampling package
  SamplingPackageRegistry().register(CommunicationSamplingPackage()); // [!code highlight]

  // 2. Create a protocol that hashes numbers, names and texts
  final protocol = SmartphoneStudyProtocol(
    ownerId: 'owner@example.com',
    name: 'Calls, messages and calendar',
    dataEndPoint: SQLiteDataEndPoint(),
    privacySchemaName: PrivacySchema.DEFAULT, // [!code highlight]
  );
  final phone = Smartphone();
  protocol.addPrimaryDevice(phone);

  // 3. Collect the call log and the calendar every 3 hours
  protocol.addTaskControl(
    PeriodicTrigger(period: const Duration(hours: 3)),
    BackgroundTask(
      measures: [
        Measure(type: CommunicationSamplingPackage.PHONE_LOG), // [!code highlight]
        Measure(type: CommunicationSamplingPackage.CALENDAR), // [!code highlight]
      ],
    ),
    phone,
  );

  // 4. Collect the text message log once a day
  protocol.addTaskControl(
    PeriodicTrigger(period: const Duration(days: 1)),
    BackgroundTask(
      measures: [Measure(type: CommunicationSamplingPackage.TEXT_MESSAGE_LOG)], // [!code highlight]
    ),
    phone,
  );

  // 5. Deploy the protocol on the first run and start sampling
  final client = SmartPhoneClientManager();
  await client.configure();
  if (client.studies.isEmpty) {
    final study = await client.addStudyFromProtocol(protocol);
    await client.tryDeployment(study.studyDeploymentId, study.deviceRoleName);
  }
  client.resume();

  // 6. Print each measurement as JSON
  client.measurements.listen((measurement) => print(jsonEncode(measurement)));

  runApp(
    const MaterialApp(
      home: Scaffold(body: Center(child: Text('Collecting data'))),
    ),
  );
}
```

## How it works

| Stage | What it does |
| --- | --- |
| **1. Register** | Makes the four measure types, the JSON types of their data and their privacy transformers known to CAMS. `CarpMobileSensing.ensureInitialized()` runs first, because registering needs an initialized CAMS. |
| **2. Protocol** | `privacySchemaName: PrivacySchema.DEFAULT` turns on the privacy transformers, which hash phone numbers, contact names, message texts and event titles. Without it, CAMS stores them in clear text. |
| **3. Calls and calendar** | `PeriodicTrigger` fires when sampling starts and then every 3 hours. Each run collects from the end of the previous run, and the first run goes back 1 day. |
| **4. Text messages** | The text message log returns every message in the inbox and the sent folder on each run, so a daily trigger keeps the duplicates down. |
| **5. Deploy** | CAMS asks for the permissions of all measures and then starts the triggers. The app adds the study only on the first run: on later runs, `configure()` restores the saved study. |
| **6. Print** | `client.measurements` delivers each measurement after the privacy transformers have run. |

The phone log and the calendar keep their last collection time in memory. After an app restart, their first run goes back 1 day again. To keep the time across restarts, see [Calls and text messages](/docs/sampling-packages/communication/calls-and-messages#configuration).

## Run the app

Connect the phone and run:

```bash
flutter run
```

On Android, CAMS asks for access to phone calls, call logs, the calendar and SMS; on iOS, it asks for calendar access only. Allow them.

The first run starts right away, and the console prints a measurement for each measure that runs on the phone. CAMS also adds a `dk.cachet.carp.triggeredtask` measurement each time a trigger fires.

## Troubleshooting

<Accordions>
<Accordion title="No call log or text messages on Android">

Check that the participant allowed every dialog, and that the permissions are in the merged manifest. An app that removes the restricted permissions for Google Play collects the calendar only. See [Installation](/docs/sampling-packages/communication/installation) for the entries each measure needs.

</Accordion>
<Accordion title="Only calendar data on iOS">

Use an Android phone to collect calls and text messages: iOS gives apps no access to them, so CAMS skips those measures on iOS.

</Accordion>
</Accordions>

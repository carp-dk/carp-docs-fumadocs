This page lists the measure types available in sampling packages, both the packages built into the [`carp_mobile_sensing`](https://pub.dev/packages/carp_mobile_sensing) framework and the external ones. The list evolves as support for more measures is released.

## Measure type format

The `dataType` property of a [`Measure`](https://pub.dev/documentation/carp_core/latest/common/Measure-class.html) specifies the type of data to collect. Its string form is typically a `namespace` plus a `name`. CAMS-native measure types use the namespace `dk.cachet.carp`, and the name is the measure `type`:

```text
dk.cachet.carp.<type>
```

<Callout type="info" title="Legacy namespace">

The `cachet` part of the namespace is a legacy. The original vision and design of CARP was done at the [Copenhagen Center for Health Technology](https://www.cachet.dk/) (CACHET), and the namespace `dk.cachet.carp` was adopted then. CACHET has since closed, and CARP is now maintained by the [Section of Digital Health](https://www.healthtech.dtu.dk/research/research-sections/section-digital-health) at the Department of Health Technology at the [Technical University of Denmark](https://www.dtu.dk/english/).

The old namespace is kept for backward compatibility. It will be changed to `carp.dk` in the future.

</Callout>

## Event-based and one-time measures

| Kind | Behavior | Example |
| --- | --- | --- |
| **Event-based** (EB) | Once triggered and started, continuously samples data from its sensor until explicitly stopped. Most measures are event-based. | A step event every time the phone detects a step. |
| **One-time** (OT) | Samples one piece of data when triggered. | Weather data from the Open Weather API. |

The kind matters when you specify a study protocol: an event-based measure can be started and runs until stopped, whereas a one-time measure must be triggered to sample data. You can, for example, trigger it periodically with a [`PeriodicTrigger`](https://pub.dev/documentation/carp_mobile_sensing/latest/domain/PeriodicTrigger-class.html).

In this protocol, the first task contains a one-time measure (device information) that is triggered only once. The second task contains event-based measures that start immediately and keep sampling data based on events. The third task collects weather (a one-time measure) periodically every 5 minutes.

```dart
  // Collect device info only once, when this study is deployed.
  protocol.addTaskControl(
    OneTimeTrigger(),
    BackgroundTask(
        measures: [Measure(type: DeviceSamplingPackage.DEVICE_INFORMATION)]),
    phone,
  );

  // Immediately start collecting step count, ambient light, screen activity, and
  // battery level events. All event-based measures.
  protocol.addTaskControl(
    ImmediateTrigger(),
    BackgroundTask(measures: [
      Measure(type: SensorSamplingPackage.STEP_EVENT),
      Measure(type: SensorSamplingPackage.AMBIENT_LIGHT),
      Measure(type: DeviceSamplingPackage.SCREEN_EVENT),
      Measure(type: DeviceSamplingPackage.BATTERY_STATE),
    ]),
    phone,
  );

  // Add a background task that collects weather every 5 minutes.
  protocol.addTaskControl(
      PeriodicTrigger(period: Duration(minutes: 5)),
      BackgroundTask(
          measures: [Measure(type: ContextSamplingPackage.WEATHER)]),
      weatherService);
```

Each [`SamplingPackage`](https://pub.dev/documentation/carp_mobile_sensing/latest/domain/SamplingPackage-class.html) lists the measure types it supports in its [`dataTypes`](https://pub.dev/documentation/carp_mobile_sensing/latest/domain/SamplingPackage/dataTypes.html) property, and provides a [default sampling schema](https://pub.dev/documentation/carp_mobile_sensing/latest/domain/SamplingPackage/samplingSchemes.html) for each of its measure types.

## Available measure types

CAMS has a large set of predefined measure types, each available in a sampling package. Some measures are [part of CAMS](#built-in-sampling-packages), others are available in [separate sampling packages](#external-sampling-packages), and some are part of [device-specific sampling packages](#wearable-device-sampling-packages).

For each measure, the tables list:

- **Type**: all type names have the format `dk.cachet.carp.<type>`, where `type` is listed in the table.
- **Android** and **iOS**: availability on each platform.
- **Package**: the sampling package that contains the measure.
- **Description**.

Types marked with \* are one-time measures.

### Wearable device sampling packages

| Type | Android | iOS | Package | Description |
| :--- | :---: | :---: | :--- | :--- |
| `health` | Yes | Yes | [`health`](https://pub.dev/packages/carp_health_package) | Different types of health data from [Apple Health](https://www.apple.com/health/) and [Google Health Connect](https://health.google/products/), which may come from connected wearable devices |
| `movisens` | Yes | No | [`movisens`](https://pub.dev/packages/carp_movisens_package) | Activity and heart rate monitoring using the [Movisens](https://www.movisens.com/en/) [Move4](https://www.movisens.com/en/products/activity-sensor/) and [EcgMove4](https://www.movisens.com/en/products/ecg-sensor/) devices |

| `polar` | Yes | Yes | [`polar`](https://pub.dev/packages/carp_polar_package) | Inertial measurement (accelerometer, gyroscope, magnetometer) and heart rate (ECG, PPI, PPG, HR) data from [Polar](https://www.polar.com/en) devices |
| `movesense` | Yes | Yes | [`movesense`](https://pub.dev/packages/carp_movesense_package) | State (tap), heart rate (HR), ECG and inertial measurement unit (IMU: accelerometer, gyroscope, magnetometer) data from [Movesense](https://www.movesense.com/) devices |
| `watch.aware` | No | Yes | [`aware`](https://pub.dev/packages/carp_aware_package) | Motion, heart rate, battery, location, heading, Bluetooth, ambient noise and sound classification collected on an [Apple Watch](https://www.apple.com/watch/) using the [AWARE](https://github.com/awareframework/com.awareframework.ios.sensor.applewatch) watchOS framework. Each of these device measures has sub-types, such as `dk.cachet.carp.movisens.hr` for heart rate (HR) measures from the Movisens device.

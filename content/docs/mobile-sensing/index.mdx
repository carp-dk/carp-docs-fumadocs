The CARP Mobile Sensing (CAMS) Flutter package [`carp_mobile_sensing`](https://pub.dev/packages/carp_mobile_sensing) is a framework for adding digital phenotyping capabilities to mobile health apps. Use it to build custom mobile sensing apps that you can adapt to very different health domains.

## Features

CAMS is built on a flexible engineering architecture that supports:

- cross-platform (Android and iOS) support
- persistent sampling state management
- multiple wearable and device integrations
- configurable data sampling and transformation
- pluggable data management and upload strategies

## What you can collect

<Cards>
<Card title="Onboard phone sensors" icon="Smartphone">

Movement data (IMU), location, nearby devices, steps, screen events and many other **measures**.

</Card>
<Card title="Wearable devices" icon="Watch">

Smartwatches (for example Apple Watch), heart rate monitors (for example Polar), ECG monitors, glucose monitors, iBeacons and other **devices**.

</Card>
<Card title="User-generated data" icon="Quiz">

Surveys, questionnaires, ecological momentary assessments (EMAs), audio, video and sound from participants.

</Card>
<Card title="Cognitive assessment" icon="Science">

14 predefined cognitive assessment tools, such as trail-making, reaction time, recall, flanker and object tracking tests.

</Card>
</Cards>

## How it works

Adding sampling to a Flutter app takes three steps:

<Steps>
<Step title="Define a study protocol">

Create a `SmartphoneStudyProtocol` that defines which **measures** to collect from which **devices**.

</Step>
<Step title="Create and configure the runtime">

Configure the `SmartPhoneClientManager` and add the study protocol to it.

</Step>
<Step title="Start data sampling">

Access the stream of collected **measurements**, use them in the app and control the execution of data sampling.

</Step>
</Steps>

### Example

This protocol samples step counts, ambient light, screen events and battery events, and stores the measurements in a local SQLite database:

```dart
import 'package:carp_core/carp_core.dart' hide Smartphone;
import 'package:carp_mobile_sensing/carp_mobile_sensing.dart';

// Create a protocol collecting steps, light, and screen and battery events
// from the phone and store collected measurements in a local SQLite database
final phone = Smartphone();
final protocol =
    SmartphoneStudyProtocol(
        ownerId: 'AB',
        name: 'Tracking steps, light, screen, and battery',
        dataEndPoint: SQLiteDataEndPoint(),
      )
      ..addPrimaryDevice(phone)
      ..addTaskControl(
        DelayedTrigger(delay: const Duration(seconds: 10)),
        BackgroundTask(
          measures: [
            Measure(type: SensorSamplingPackage.STEP_EVENT),
            Measure(type: SensorSamplingPackage.AMBIENT_LIGHT),
            Measure(type: DeviceSamplingPackage.SCREEN_EVENT),
            Measure(type: DeviceSamplingPackage.BATTERY_STATE),
          ],
        ),
        phone,
      );

// Create and configure a client manager for this phone.
await SmartPhoneClientManager().configure();

// Create a study based on the protocol.
var study = await SmartPhoneClientManager().addStudyFromProtocol(protocol);

// Deploy the study.
await SmartPhoneClientManager().tryDeployment(
  study.studyDeploymentId,
  study.deviceRoleName,
);

// Resume sampling.
SmartPhoneClientManager().resume();

// Listening on the measurements stream.
SmartPhoneClientManager().measurements.listen((measurement) {
  // Do something with the measurement, e.g. print the json.
  print(toJsonString(measurement));
});

// Pause sampling.
SmartPhoneClientManager().pause();

// Resume sampling again.
SmartPhoneClientManager().resume();

// Dispose the client. Can not be used anymore.
SmartPhoneClientManager().dispose();
```

### Minimal example

You can configure the client manager, add the protocol and start sampling in a single statement:

```dart
SmartPhoneClientManager().configure().then(
  (_) => SmartPhoneClientManager()
      .addStudyFromProtocol(
        SmartphoneStudyProtocol.local(
          name: 'Tracking steps, light, screen, and battery',
          measures: [
            Measure(type: SensorSamplingPackage.STEP_EVENT),
            Measure(type: SensorSamplingPackage.AMBIENT_LIGHT),
            Measure(type: DeviceSamplingPackage.SCREEN_EVENT),
            Measure(type: DeviceSamplingPackage.BATTERY_STATE),
          ],
        ),
      )
      .then(
        (study) => SmartPhoneClientManager()
            .tryDeployment(study.studyDeploymentId, study.deviceRoleName)
            .then((_) => SmartPhoneClientManager().resume()),
      ),
);
```

<Callout type="tip" title="Persistent sampling">

Once a study is defined (through a protocol), added, deployed and resumed, CAMS saves its entire state persistently across app restarts. You do not need to restore studies or restart data sampling when the app is closed and restarted, even when the OS kills it. See [background sensing](/docs/mobile-sensing/best-practices#background-sensing).

</Callout>
